# GIP for Goodle

## Guided Iterative Precision

Goodle adopts the Tehkné GIP discipline as its execution methodology.

### Phase 0 — Discovery

Intent, users, constraints, risks, acceptance criteria.

### Phase 1 — Architecture

Project model, stack/runtime target, systems, dependencies, folder/package plan.

### Phase 2 — Development

Micropass execution, specialized roles, bounded changes, generated artifacts.

### Phase 3 — Validation

Functional/visual validation, changelog, evidence, regression checks, process checkpoint.

### Phase 4 — Release

Package, publish, deployment evidence, README/release notes.

## Process commit

A validated change becomes a checkpoint. The historical Tehkné workflow established that every executor change should produce a detailed CHANGELOG before the next phase proceeds.

## Anti-regression protocol

Never modify already-validated functionality merely because a new feature is being added. New work must preserve known invariants or explicitly request a change to them.
