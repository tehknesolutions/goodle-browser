# Goodle IR V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fazer um pequeno programa OldRewrite convergir para Goodle IR semanticamente validado e executável por um runtime inicial sem acoplamento do parser ao runtime.

**Architecture:** O Parser produz nós `GoodleIRNode`; o Semantic Bridge resolve termos para IDs canônicos; o validador rejeita IR estrutural ou semanticamente inválido; o HyperKernel despacha nós válidos para adaptadores de runtime. O primeiro runtime será mínimo e determinístico, suficiente para provar a arquitetura sem congelar HEPGA nem tentar reproduzir engines inteiras.

**Tech Stack:** TypeScript, Vitest, arquitetura existente `src/nucleo`, Semantic Dictionary V1, runtime TypeScript existente no repositório.

**Spec:** `docs/arquitetura/GOODLE-IR-SPEC-V1.md`

## Global Constraints

- PT-BR é a forma canônica de apresentação e documentação.
- Entrada aceita PT-BR com ou sem acentos, inglês ou mistura.
- O IR não é código final de nenhuma engine.
- IDs semânticos vêm do Semantic Dictionary V1; não criar vocabulário paralelo.
- Origem, termo e nível de equivalência devem poder ser preservados.
- Parser não pode conter lógica específica de Phaser, Godot, BYOND, RPG Maker ou runtime final.
- Vibecoding, low-code, block-code, GAIC e escrita manual devem poder convergir futuramente para o mesmo IR.
- Composição e simplicidade têm prioridade sobre abstrações prematuras.
- CI atual possui bloqueio de infraestrutura; nenhum resultado deve ser declarado GREEN sem execução verificável.

## Review Focus

- Entrada com acentos, sem acentos e mistura PT-BR/EN deve convergir para a mesma semântica quando o dicionário declarar equivalência.
- Termo contextual sem origem suficiente deve gerar diagnóstico, não resolução arbitrária.
- ID semântico inexistente no dicionário deve ser rejeitado pelo validador.
- Árvore com filhos inválidos deve reportar o caminho do nó inválido sem perder os demais diagnósticos.
- Runtime que não implementa uma semântica válida deve responder `nao_suportado`, nunca executar fallback silencioso.
